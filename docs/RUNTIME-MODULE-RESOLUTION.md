# Runtime Module Resolution

Next.js/Turbopack must resolve executable workspace package imports to JavaScript modules, not TypeScript declaration files.

Incorrect:

```json
{
  "paths": {
    "@powerchain/utils/http": [
      "../../packages/utils/dist/http.d.ts"
    ]
  }
}
```

That alias is type-only but Next.js may also honor it during bundling. The resulting client bundle can replace a missing runtime export with `undefined`, producing errors such as:

```text
(void 0) is not a function
```

PowerChain now relies on pnpm workspace links plus each package's `exports` map for runtime resolution.

Before `dev` or `build`, package outputs are generated by `build:packages`.

Validation:

```bash
pnpm doctor:runtime-resolution
pnpm doctor:frontend
pnpm typecheck
```
